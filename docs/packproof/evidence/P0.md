## Mandatory gates and workshop pattern

Inspected the linked workshop's actual `submit_memo.py` and `set_checklist.py`. The useful pattern is validation **inside the action handler**, returning structured refusal feedback before a durable result is filed. Workshop memo checks escalate after repeated refusals. Its optional verification-off mode and checklist acceptance after three attempts are deliberately excluded from PackProof.

P0 implements strict contracts, typed read-only dispatch, independent fact matching, parser checks and exact-byte crypto checks. The following are documented execution boundaries for later phases, **not claims that those services exist**:

| Boundary | Mandatory execution location |
| --- | --- |
| Lookup/issuer/marking | Server lookup handler/shared domain verifier; check scoped issuer authority and mappings before returning facts |
| Investigation conclusion | Server finalizer after any model loop; require product/issuer, relationship, seller, notices and history coverage even when Muse omits a tool; missing checks yield needs_evidence |
| Visual finding | Capture/inspection handler + domain verifier; validate capture revision/hash, SAM region, literal reading/quality, provenance and physical association separately |
| Transfer scan/approval/confirm | Authenticated transfer service for identity/key/signature/nonce/direction/consent/policy; privileged DB transaction rechecks current owner/version/conflicts and consumes challenges atomically |
| Receipt/export | Server signing boundary after validated committed result; no model-held issuer/server private keys |
| Offline import | Shared static verifier: schema/size → pinned root/directory → pack signer → exact-byte hashes/dependencies → record issuer role/signature → scope/version → freshness; invalid data never replaces a prior accepted pack |

No LLM flag disables mandatory checks; repeated failures stay unresolved/blocked rather than graduating to success. Legal-domain rules are not imported.
