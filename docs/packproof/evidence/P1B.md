## Six tools and model execution

All exact H2 names have strict required/nullable inputs and validated GateResult outputs. Product/seller/notice/history call the actual P1A signed-source services. Tool scope is bound to the investigation’s namespace, product, seller and authorized capture; a valid foreign UUID cannot redirect a tool to another item or private investigation. No tool can transfer or modify registered ownership.

`inspect_product_image` authorizes the owned capture/revision and handles private image metadata/provenance. For the exact saved synthetic P0 image only, it replays the authentic SAM special-token bytes through the installed parser and reuses the saved literal Muse reading `0071842`. A different image stays unknown; the expected database code is never substituted as a reading. A saved literal differing from the requested code yields a discrepancy. Image/capture references are genuine stored capture IDs; no new signed inspection or fabricated mask-record IDs are minted. Physical association stays unresolved. **No new segmentation/reading request, complete P3 Inspector or physical success claim.**

`request_additional_evidence` persists a needs-input request with an exact view/instruction. LangGraph pauses after a mandatory preliminary assessment. On resume, only validated user observations/captures and the next revision enter `Command({resume})` on the same authorized thread.

The actual LangChain adapter serializes Muse Spark 1.3 function tools using the proven gateway settings, real LangChain tool invocation and structured final-answer schema. Production demo planning uses **deterministic P1 choices in a reconstructed proven P0 Chat Completions envelope shape**. Original P0 compatibility regressions still exercise its recorded provider metadata. The new P1 decisions are not untouched historic Meta responses or new live inference. The interface and telemetry explicitly label replay mode. New live Muse/SAM calls stay disabled; changing a public request cannot enable them. An operator’s future authorized live transport needs its separately approved budget integration/validation.

The model chooses from verified fact IDs. The finalizer renders the corresponding verified sentences and signed source references; arbitrary model text, invented citations, notices, ownership or safety claims cannot become the explanation.

## Independent finalization and durable limits

Every final assessment rereads issuer/product/mapping, seller, notices and history independently, even if Muse omitted a tool. Omitted coverage remains needs_evidence; unknown or unauthorized claims remain blocked/unresolved. Provider/argument/output/budget failure never becomes supported. Notice applicability retains issuer/model/batch/date/correction scope. Existing custody gaps remain unresolved. Retrieval times and dated custody snapshots are checked against the declared 24-hour demo freshness limit; rereading an old snapshot does not refresh its age. Record consistency, registered seller authorization and physical association remain separate fields.

The only controller is StateGraph: plan → typed tool → optional preliminary assessment/interrupt → resume → mandatory finalizer. Maximums **8 tool actions, 3 recapture requests, 2 total transient-provider retries** persist in Postgres across resumes. SDK retries remain zero; the controller owns retries. Model requests have a durable bound, default session timeout is 10 minutes (configurable up to one hour), and the session reservation cap defaults to 50 cents (maximum 50, not authorization to spend). Recorded requests reserve zero; no live-price claim is made. The old ProbeBudget validator is reused for fail-closed live gating without writing/resetting its exhausted ledger.

Operation keys bind investigation, operation, revision and canonical argument hash. Completed repeats reuse their exact stored result; changed arguments conflict. An interrupted reserved operation fails closed as in doubt rather than silently repeating an ambiguous effect. Checkpoint replay does not reset counters. Mandatory read-only finalizer checks are separately labeled from the model’s counted actions.

Public product lookup exposes signed public facts; private investigations/checkpoints/captures cannot be retrieved by another session.

Uploads accept bounded, actually decoded JPEG/PNG only: 2 MiB maximum, 4096×4096 maximum, no multi-page content, at most six captures per investigation. Original bytes/hash, dimensions, source, untrusted capture time, upload time and revision are retained. The server authorizes the investigation before using the private Storage key; no browser receives it or an unrestricted media URL. Actual synthetic image upload, anonymous-object denial and foreign capture denial passed. The controlled Storage test object is deleted after testing; no customer media was uploaded.

Actual integration covers the P1A regression suite plus P1B graph restore, duplicate/changed resume, RLS across sessions/checkpoint rows/operations/captures, denied claim/ownership writes and private Storage/parser handling. ## Evidence-check latency follow-up — 2 November 2026

The user reported slow checking. A new `scripts/p1b/benchmark.ts before|after` measures a real cold owner-scoped runtime and signed Supabase reads with recorded model responses. It logs aggregate query counts/timings only, never SQL/arguments, session identifiers or secrets. Actual measurements: **26,936 ms → 15,579 ms (42.2% shorter)**, **240 → 219 queries**, **15 → 3 connections**. These are one sample per version from this laptop, excluding HTTP/dev compilation overhead; they are not a production latency guarantee or live Muse measurement. See [before](p1b-latency-before.json) and [after](p1b-latency-after.json).

The one-second connection idle timeout was disconnecting clients between graph steps. Request-owned pools now keep clients idle for up to 30 seconds, retain the three-client bound and close when the request ends. Independent seller/notice/history finalizer reads run together, still independently loading and cryptographically validating signed sources; every audit write settles before a finding can complete. Private saves use an RLS-protected UPDATE RETURNING to detect missing/foreign investigations without a redundant read. Budget/counter and operation reservation writes share one atomic statement within the existing locked transaction. Single-operation completion uses an atomic UPDATE; tool completion plus its event still uses its explicit transaction. Row locks, the separate idempotency read after locking, all limits, TLS verification and the official checkpoint saver remain. No claim/source cache, schema migration, altered signed records, skipped finalizer or weakened persistence.

Validation on the final change: `pnpm typecheck`; `pnpm test --reporter=json --outputFile=docs/packproof/evidence/vitest-p1b-performance-unit.json` (**100 passed**); `PACKPROOF_P1A_INTEGRATION=1 PACKPROOF_P1B_INTEGRATION=1 pnpm test:integration --reporter=json --outputFile=docs/packproof/evidence/vitest-p1b-performance-integration.json` (**10 actual Supabase tests passed**); `NEXT_TELEMETRY_DISABLED=1 pnpm build`; `pnpm probe:bundle`.
